# 健身数据规范记录 Skill

给 Hermes Agent 用的配套技能：用户用一句话（微信、终端、任意接进来的入口）说今天练了什么、吃了什么，Agent 按下面的格式追加到 `fitness_log.md`，`parse_fitness.py` 负责解析成网页要的 `data.json`。

### ⚠️ 铁律

**绝对禁止**预生成未来日期的空模板。只能在用户明确提供数据时，追加到已有日期或创建新日期。禁止写 `（待记录）` 占位符，禁止批量创建空白日期条目。违者数据丢失。

**绝对禁止直接编辑 `fitness_log.md`**。若按仓库里的 `safe_write_fitness.sh` 部署，日志文件已被 `chattr +i` 内核锁定，任何工具（包括 root）都无法直接 echo/cat/sed/python 写入，会被内核拒绝（`Operation not permitted`）。`chattr` 是 Linux 专有，服务器上生效，本机 macOS 上跑不出这个效果。

**唯一写入方式**：

```bash
echo '新内容' | bash safe_write_fitness.sh
```

该脚本自动：`chattr -i` 解锁 → 写入 → 解析校验（天数不减少则拒绝） → `chattr +i` 上锁。校验失败会自动回滚到 `fitness_backups/` 中的最近备份。

## 数据文件

- 文件：`fitness_log.md`（与解析脚本同目录，路径自己定）
- **只追加，不修改已有内容**
- 每次记录追加到文件末尾

## 记录格式规范

### 1. 日期标题（必须）

```
### YYYY-MM-DD（周X）
```

示例：`### 2026-07-12（周日）`

### 2. 体重记录（重要！）

**每个训练日或称重日，在日志正文中记录体重：**

```
- 体重：**63.35kg**
```

或带体脂秤数据：
```
#### ⚖️ 体测（Zepp Life）
- 体重：**63.35kg**（126.7斤）| 身体得分 90分
- BMI：24.1（偏高）| 体脂：**19.7%**（标准）| 肌肉：48.2kg（标准）
```

**格式要点**：
- 必须包含 `体重：**数字kg**`，数字和 kg 之间不要有空格
- 支持 `体重：**63.35kg**` 和 `体重：63.35kg` 两种格式
- **不需要手动更新顶部体重表**——解析器会自动从日志正文提取并合并到趋势图
- 体测其他数据（BMI/体脂/肌肉等）会被自动过滤，不会误识别为训练动作

### 3. 饮食记录（强制格式）

**⚠️ 必须严格按此格式，否则解析器无法识别。**

每行格式：
```
- 食物名 | 热量kcal | 蛋白Xg | 碳水Xg | 脂肪Xg
```

示例：
```
### 饮食
#### 早餐
- 鸡蛋 ×2 | 150kcal | 蛋白12g | 碳水1g | 脂肪10g
- 全麦面包 ×1 | 130kcal | 蛋白5g | 碳水24g | 脂肪2g
- 纯牛奶 250ml | 160kcal | 蛋白8g | 碳水12g | 脂肪8g

#### 午餐
- 鸡胸肉 120g | 200kcal | 蛋白35g | 碳水0g | 脂肪4g
- 米饭 400g | 520kcal | 蛋白10g | 碳水144g | 脂肪1g

#### 晚餐
- 土豆牛肉盖饭 | 650kcal | 蛋白35g | 碳水70g | 脂肪22g

#### 补剂
- 乳清蛋白粉 30g | 115kcal | 蛋白22g
- 一水肌酸 3g | 0kcal | 蛋白0g
```

**格式铁律**：
- 分隔符必须是 ` | `（竖线前后有空格）
- 第二列必须是 `数字kcal`（如 `150kcal`、`~140kcal`）
- 第三列必须是 `蛋白数字g`（如 `蛋白12g`）
- 第四列必须是 `碳水数字g`（如 `碳水24g`）
- 第五列必须是 `脂肪数字g`（如 `脂肪10g`）
- **不要**在数字和 kcal/g 之间加空格（写 `150kcal` 不写 `150 kcal`）
- 补剂行至少要有 `数字kcal | 蛋白数字g`
- 小计行用 `**` 包裹，不用 `|` 分隔符

早期版本的解析器不认 `~` 前缀和千位逗号，现在都支持了（`~150kcal`、`1,006kcal` 都能读），但这两种写法仍需保持一致，别混着写。

### 4. 训练记录

```
### 训练
**💪 今日训练：部位**

- 动作名 | 组数信息 | 重量详情
```

示例：
```
### 训练
**💪 今日训练：腿**

- 杠铃深蹲 | 4组 | 80kg×5×4
- 俯卧腿弯举 | 4组 | 30kg×10×2 + 35kg×7×2
- 山羊挺身 | 4组 | 20kg×8×4
```

**格式要点**：
- 部位用中文：腿/胸/背/肩/手臂/腹
- 多部位用 `+`：`胸 + 三头`、`背 + 腹`
- 有氧用：`有氧：跑步` 或 `有氧：排球`
- 动作格式：`- 动作名 | X组 | 重量×次数`
- 自由格式也支持：`- 动作名 | 重量×次数` 或 `- 动作名 | 次数详情`
- 训练记录放在 `### 训练` 标题下

### 5. 修改目标体重

用户说"改目标体重到 70kg"、"目标改成 70"时，修改日志顶部 `目标体重：~68kg` 行，改完重跑一次解析脚本。

## 完整示例

用户说："今天练了背+腹，记一下"

你应该追加：

```
### 2026-07-12（周日）

### 训练
**💪 今日训练：背 + 腹**

- 对握下拉 | 4组 | 40kg×8×4
- 高位下拉 | 4组 | 50kg×8×4
- 悬垂举腿 | 4组 | 15次×4
```

## 关键规则

1. **不修改已有内容**：只追加，不改写
2. **日期标题必须有**：`### YYYY-MM-DD（周X）`
3. **部位用中文**：腿/胸/背/肩/手臂/腹
4. **动作分隔用 `|`**：竖线前后有空格
5. **重量中的乘号用 `×`**（不是字母 x）
6. **体测数据单独一栏**，不要混在训练或饮食里

## ⚠️ 数据完整性 — 致命漏洞

**永远不要写"（待记录）"。** 如果用户提供了数据，必须完整记录；如果用户没说具体吃了什么/练了什么，写明"未提供"而非"（待记录）"。

**"（待记录）"的后果**：
- 解析器看到 `#### 早餐\n（待记录）` → 跳过该餐 → 热量和蛋白统计偏低
- 用户回头看时以为 Agent 记了但数据丢了，实际上根本没记

**正确做法**：
- 用户说了具体食物 → 完整记录每一行
- 用户说了"吃了午饭"但没细节 → 问一下具体吃了什么
- 用户完全没提某餐 → 不写这一餐，不要写"（待记录）"
- 用户说"今天休息" → 写 `### 训练\n休息日` 而不是空着

### 🔑 写入后必须验证

**致命问题**：Agent 说"已记录 ✅"但日志文件实际没变，这种情况真实发生过多次，一整周的训练数据丢失。

**强制验证流程**：每次写入后立即执行：

```bash
tail -5 fitness_log.md
```

确认刚写入的内容确实存在。验证失败就重写。**在看到 tail 输出确认写入成功之前，不得告诉用户"已记录"。**

## 同步节奏

改完日志后跑一次 `python3 parse_fitness.py` 就会更新 `data.json`；长期用建议挂个每 10 分钟的定时任务（`*/10 * * * *`），比指望自己记得跑可靠得多。解析器带 SHA256 增量判断，数据没变会直接跳过，不会白白刷新前端缓存。
